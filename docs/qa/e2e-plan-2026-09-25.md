# End-to-end test plan — 2026-09-25

Deep testing of the product **from the UI**, against the dev server on :3000 and the real
development database. Two instruments, deliberately: the founder's real Chrome (the Claude
extension, signed in as the founder) drives the journey a consultant actually sees, one surface at
a time; headless Playwright drivers run in parallel for breadth, one per area, each owning a
disjoint slice of the code so fixes cannot collide. Every finding is fixed on the fly by the owner
of that slice or routed to whoever owns it; nothing is marked passed on inspection.

Status legend: ☐ not run · ✅ passed · ❌ failed (issue linked) · 🔧 fixed and re-run · ⏭ blocked

## Areas and owners

| Area | Owner | Files the owner may edit |
|---|---|---|
| A · Identity & firm | real browser (main session) | `src/app/signup`, `src/app/login`, `src/app/(app)/settings` (profile/team/branding/disclaimer parts), `src/lib/actions/{org,team,auth}*`, `src/lib/auth/**` |
| B · Engagements, audits, findings, evidence | headless driver B | `src/app/(app)/engagements/**`, `src/lib/actions/{engagements,audits,evidence}.ts`, `src/lib/audit/**` |
| C · Reports, PDF, portal, access trail, cross-tenant via URL | headless driver C | `src/app/portal/**`, `src/app/api/reports/**`, `src/app/api/evidence/**`, `src/lib/actions/{reports,portal}*.ts`, `src/lib/reports/**`, `src/lib/portal/**` |
| D · Settings: billing, API keys, webhooks, retention; console/viewport sweeps | headless driver D | `src/app/(app)/settings` (billing/api-keys/webhooks/retention parts), `src/app/api/v1/**`, `src/lib/actions/{billing,apiKeys,webhooks}*.ts`, `src/lib/api/**`, `src/lib/webhooks/**` |

Rule: a finding outside your slice is **reported, not fixed**. The main session routes it.
